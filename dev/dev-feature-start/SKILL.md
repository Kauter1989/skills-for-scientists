# dev-feature-start — старт фичи с тестами до кода

Навык создаёт ветку и `overview.md`, в котором зафиксирован порядок:
stories → поведенческие тесты → функциональные тесты → красный гейт →
реализация → зелёный гейт.

Нормативные документы:

| Файл | Содержание |
|---|---|
| `references/feature-checklist.md` | чек-лист старта |
| `references/test-gates.md` | правила stories, тестов и red/green |
| `templates/overview.md` | шаблон brief |
| `scripts/start_feature.py` | ветка и brief |

> Если `skill` tool не видит навык, положите каталог в
> `.opencode/skill/dev-feature-start/` или
> `~/.config/opencode/skill/dev-feature-start/`.

## Когда применять

- начинается новая фича;
- нужно создать ветку от свежей основной;
- нужен brief с user stories и критериями приёмки;
- нужно зафиксировать red/green гейты до кода.

## Когда не применять

- уже есть утверждённый brief — переходите к `dev-spec-chain`;
- это багфикс — используйте `dev-repro-first`;
- нужен только отчёт об изменениях — это `dev-pr-report-html`;
- нет привязки к плану и нет обоснования.

## Вход

- slug фичи;
- цель и пункт плана или обоснование;
- владелец;
- основная ветка;
- режим утверждения: `user` или `autonomous`.

## Процедура

1. **Проверить дерево.** `git status --short` должен быть пустым.
2. **Создать ветку и brief.**

   ```bash
   python scripts/start_feature.py my-feature \
     --root /path/to/repo \
     --plan-item P12 \
     --owner team \
     --approval-mode user
   ```

   Для проверки без изменений — `--dry-run`.

3. **Заполнить user stories.** `US-*` с критериями приёмки.
4. **Утвердить stories.** Пользователь или автономный режим; записать в
   журнал утверждений.
5. **Заполнить и утвердить поведенческие тесты.** `B-*` привязаны к `US-*`.
6. **Заполнить и утвердить функциональные тесты.** `F-*` и границы.
7. **Реализовать тесты первыми.** Запустить прогон; он должен быть
   **красным**. Записать команду, падения и дату.
8. **Реализовать задачи.** Только после красного гейта.
9. **Добиться зелёного полного прогона.** Записать команду и результат.
10. **Передать в spec-chain/ревью.** Не делать commit и merge без решения.

## Выход

- ветка `feature/<slug>`;
- `docs/features/<slug>/overview.md` с US/B/F и статусами;
- журнал утверждений;
- evidence красного и зелёного гейтов.

## Доказательства

- ветка создана от свежей основы;
- brief содержит US/B/F и red/green;
- stories и тесты утверждены до реализации тестов;
- красный гейт: команда и список падений;
- зелёный гейт: полный прогон;
- повторный запуск не перезаписывает brief без `--force`.

## Границы

- Не пишет `spec.md`, `plan.md` и задачи.
- Не реализует код и тесты.
- Не делает commit, push и merge.
- Не утверждает stories за пользователя в режиме `user`.
- Не создаёт ветку из грязного дерева без `--allow-dirty`.

## Типовые ошибки

- ветка от устаревшей основной;
- brief без критериев приёмки;
- тесты пишутся после кода;
- красный гейт не зафиксирован;
- зелёный только на новых тестах;
- stories изменены после red без повторного утверждения.

## QA

- [ ] дерево было чистым;
- [ ] ветка создана от свежей основы;
- [ ] brief содержит US/B/F;
- [ ] режим утверждения записан;
- [ ] stories и тесты утверждены до тестов;
- [ ] красный гейт подтверждён;
- [ ] реализация начата после red;
- [ ] зелёный гейт — полный прогон;
- [ ] commit/push не сделаны без решения.
