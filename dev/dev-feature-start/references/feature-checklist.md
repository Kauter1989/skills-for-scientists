# Чек-лист старта фичи

Нормативный документ `dev-feature-start`. Определяет, что должно быть
сделано до первой строки кода.

## 1. Ветка

- [ ] рабочее дерево чистое;
- [ ] основная ветка обновлена (`git fetch origin`);
- [ ] ветка `feature/<slug>` создана от свежей основы;
- [ ] slug в нижнем регистре через дефис.

## 2. Привязка

- [ ] указан пункт плана или обоснование вне плана;
- [ ] владелец фичи известен;
- [ ] база (`main` или другая) зафиксирована.

## 3. Feature brief

`docs/features/<slug>/overview.md` содержит:

- [ ] цель и границы;
- [ ] что не входит;
- [ ] user stories `US-*` с критериями приёмки;
- [ ] режим утверждения `user` или `autonomous`;
- [ ] поведенческие тесты `B-*`, привязанные к `US-*`;
- [ ] функциональные тесты `F-*`;
- [ ] красный гейт;
- [ ] задачи `T-*`;
- [ ] зелёный гейт;
- [ ] журнал утверждений;
- [ ] риски.

## 4. Гейты

- [ ] stories утверждены;
- [ ] поведенческие тесты утверждены;
- [ ] функциональные тесты утверждены;
- [ ] тесты реализованы первыми;
- [ ] красный гейт зафиксирован;
- [ ] только после него начата реализация;
- [ ] зелёный гейт — полный прогон.

## 5. Границы

- `start_feature.py` не пишет spec.md и plan.md;
- не делает commit, push, merge;
- не перезаписывает brief без `--force`;
- не создаёт ветку из грязного дерева без `--allow-dirty`.

## 6. Приёмка

- [ ] ветка и brief создаются на чистом репозитории;
- [ ] повторный запуск отклоняется;
- [ ] грязное дерево отклоняется;
- [ ] `overview.md` содержит все разделы;
- [ ] red/green гейты видны в brief.
