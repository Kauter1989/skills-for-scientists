# {{STAGE_TITLE}} — {{REPO}}

Стадия цепочки `{{APPROACH}}`. Выполняется после предыдущей стадии и до
следующей; не пропускает гейты.

## Когда применять

- фича дошла до стадии {{STAGE_TITLE}};
- предыдущий артефакт существует и утверждён;
- нужен следующий артефакт цепочки.

## Когда не применять

- предыдущая стадия не завершена;
- нет `overview.md` с утверждёнными stories;
- запрос относится к другой стадии.

## Вход

- `{{INPUT}}`;
- утверждённый `overview.md`;
- ограничения и гейты из `.opencode/spec-chain.yml`.

## Процедура

1. Проверить входной артефакт и статус предыдущего гейта.
2. Выполнить стадию по правилам `{{APPROACH}}`.
3. Проверить traceability к `US-*` и тестам.
4. Записать результат в `{{OUTPUT}}`.
5. Обновить статус стадии и evidence.

## Выход

- `{{OUTPUT}}`;
- запись о гейте `{{GATE}}`.

## Доказательства

- входной артефакт существует и утверждён;
- выходной артефакт создан;
- traceability проверена;
- `check_spec_chain.py` проходит.

## Границы

- Стадия не выполняет работу других стадий.
- Не пишет код, если это не implement.
- Не меняет утверждённые stories без повторного approval.

## Типовые ошибки

- пропуск предыдущей стадии;
- артефакт без traceability;
- изменение stories без повторного утверждения;
- implement раньше `T-TEST-*`.

## QA

- [ ] входной артефакт утверждён;
- [ ] выходной артефакт создан;
- [ ] traceability есть;
- [ ] гейт записан;
- [ ] `check_spec_chain.py` проходит.
