# Визуализация данных: диаграммы, таблицы, схемы, KPI

Принцип: **каждое числовое утверждение отчёта должно быть предъявлено
визуально** — диаграммой, таблицей или KPI-карточкой. Текст лишь
интерпретирует визуал («главный вывод» + 2–4 пункта).

## 1. Выбор типа диаграммы

| Отношение в данных | Тип | `kind` в build_deck.py |
|---|---|---|
| Сравнение категорий | столбчатая вертикальная | `col` |
| Сравнение категорий, длинные подписи / ранжирование | горизонтальная | `bar` |
| Состав целого по категориям (накопление) | stacked | `col_stacked`, `bar_stacked` |
| Динамика во времени | линейная с маркерами | `line` |
| Накопление во времени | area | `area` |
| Доля целого (одна размерность, ≤6 категорий) | круговая / кольцевая | `pie`, `doughnut` |
| Зависимость двух величин (корреляция) | точечная | `scatter` |
| Один ключевой показатель | KPI-карточка, не диаграмма | слайд `kpi` |

Запрещены: 3D-эффекты, объёмные круговые, «спидометры», лепестковые
диаграммы для сравнения величин, более 6 серий на одной диаграмме, более
7 категорий в круговой (остальное — «Прочие»).

Комбинированные диаграммы (столбцы + линия по второй оси) допустимы только
когда вторая величина качественно иная (например, «объём, млн ₽» +
«доля, %»). В build_deck.py комбо не реализовано — собирайте такой слайд
из шаблона или двумя наложенными диаграммами.

## 2. Оформление диаграммы (настройки уже заданы в build_deck.py)

- **Палитра** — последовательные цвета бренда (`series` в пресете); первая
  серия — основной ink, вторая — акцент. Не раскрашивать все категории
  радужно: цвет несёт смысл (базовый период vs отчётный, план vs факт).
- **Подписи значений** включены; формат — из спецификации
  (`number_format`: `"0 %"`, `"#,##0"`, `"0,0"`).
- **Легенда**: сверху, только при ≥2 сериях; при одной серии — название
  серии убрать, подписать ось.
- **Сетки**: только горизонтальные, светлые (panel), 0,5 pt; вертикальные —
  отключены. Оси без засечек.
- **Заголовки осей** — с единицами измерения: «Часы», «млн ₽», «Доля, %».
- **Шрифт** 9,5–10 pt для подписей осей, без курсива.
- **Диаграмма** занимает 60–70 % ширины слайда; справа — интерпретация.
- **Заголовок диаграммы** задаётся явно (`chart.title`) или отключается.
  Не оставляйте `autoTitleDeleted=0` без `<c:title>`: PowerPoint подставит
  имя серии и продублирует заголовок слайда.
- Под диаграммой или в строке источника — происхождение данных:
  «Источник: внутренние замеры, сентябрь 2026».

## 3. Таблицы

- Строка шапки: фон ink, белый полужирный текст 11 pt.
- Корпус: зебра (белый / panel2), 10,5 pt; первая колонка полужирная
  (наименования); числа — по правому краю, текст — по левому.
- Не более 8 строк данных и 6 колонок; иначе — разбить на две таблицы,
  вынести детали в приложение или заменить диаграммой.
- Таблицу выравнивайте по верху (`align: "top"`), а не по центру: иначе
  над короткой таблицей возникает пустота в 1,5–2″.
- Для проектора кегль таблицы ≥ 14 pt; высота строки рассчитывается от
  кегля (`font_size`, `row_height`), а не фиксируется в дюймах.
- Единицы — в шапке колонки («Время, ч»), не в каждой ячейке.
- Итоговая строка («Итого», «Среднее») — допустима и полезна; выделяется
  фоном panel.
- Таблица уместна, когда читателю нужны **точные значения**; диаграмма —
  когда важна **форма зависимости**. Таблица из 2 колонок и 2 строк —
  почти всегда хуже диаграммы или KPI.

## 4. KPI-карточки («большие числа»)

- 2–4 карточки в ряд; значение 34–44 pt полужирным head-шрифтом.
- Высота карточки — по содержимому (`card_height`), а не фиксированные
  2,8″: иначе на слайде остаются пустые панели.
- Цвет по семантике: нейтральный показатель — ink; положительный эффект —
  accent (зелёный в ОПИ); риск/отрицательная динамика — терракота/красный
  ряда accent; вторичный — accent2. В спецификации build_deck.py задаётся
  полем карточки `"color_role": "ink|accent|accent2|muted"` или явным
  `"color": "1B6B3A"`; по умолчанию — ротация ink/accent/accent2/ink2.
- Подпись — что измеряется (1–2 строки, 11–12 pt); дельта — приглушённым
  («+4 п.п. к плану», «−12 % г/г»).
- Ниже ряда — блок интерпретации («Значение для бизнеса», «Ограничения»).
- Формат числа: знак эффекта обязателен («−80 %», а не «80 %»);
  направление — из подписи, не из цвета alone (цвет + знак + слово).

## 5. Схемы и диаграммы без данных (собираются фигурами)

Для маршрута «из шаблона» и ручных композиций (макет Blank):

- **Архитектура/конвейер**: горизонтальный поток блоков со стрелками
  (шевроны), каждый блок — этап + 1 строка описания; этапы нумеруются.
  Прототип: ОПИ slide 2 — «Чтение файла → Профиль → Геометрия → Расчёт →
  Характеристики».
- **Слоистая архитектура**: стеки прямоугольников снизу вверх (инфраструк-
  тура → платформа → прикладной слой), подписи слева. Прототип: Harness
  slide 8 — стек «IDE / Harness / AI OS».
- **Матрица 2×2**: оси-критерии, квадранты — панели panel/panel2, объекты
  в квадрантах; используется для сравнения аналогов и приоритизации.
- **Сравнение «было / стало»**: две панели side-by-side, различия
  полужирным; цифры эффекта — акцентным цветом.
- Цвета блоков — только из палитры бренда (ink, ink2, accent, accent2,
  panel, panel2); текст на тёмных блоках — on_dark.
- Соединительные линии — 0,75–1,5 pt, цвет muted или ink; стрелки только
  там, где есть направление процесса.

## 6. Изображения и скриншоты

- Скриншоты интерфейса/чертежа — в рамке panel 1 pt, с подписью-пояснением
  (кегль 10, muted) и указанием источника; кадрировать до содержательной
  области, не масштабировать непропорционально.
- Фотографии в аналитическом отчёте — исключение; только если несут
  информацию (стенд, прототип, результат измерений).
- Логотипы — только на титуле и в колонтитуле, монохромные.

## 7. python-pptx: шпаргалка соответствий

```python
from pptx.chart.data import CategoryChartData
from pptx.enum.chart import XL_CHART_TYPE
XL_CHART_TYPE.COLUMN_CLUSTERED   # col
XL_CHART_TYPE.COLUMN_STACKED     # col_stacked  (plot.overlap = 100)
XL_CHART_TYPE.BAR_CLUSTERED      # bar
XL_CHART_TYPE.LINE_MARKERS       # line
XL_CHART_TYPE.AREA               # area
XL_CHART_TYPE.PIE / .DOUGHNUT    # pie / doughnut (точки серии красятся individually)
XL_CHART_TYPE.XY_SCATTER_LINES_NO_MARKERS  # scatter (XyChartData)
# Подписи значений: plot.has_data_labels = True; plot.data_labels.number_format = "0 %"
# Сетка: value_axis.has_major_gridlines; .major_gridlines.format.line.color.rgb
# Заголовок оси: axis.has_title = True; axis.axis_title.text_frame.text = "Часы"
# Цвет серии: series.format.fill.solid(); .fore_color.rgb = RGBColor.from_string("002060")
```

Типовые ошибки: `data_labels.position` задаётся строго по типу диаграммы —
`outEnd/inEnd` допустимы только для столбчатых/полосчатых; у line/scatter
PowerPoint отклоняет их **вместе с файлом** (line → ABOVE/BELOW/LEFT/RIGHT,
scatter → позицию не задавать); area не поддерживает подписи значений
(`has_data_labels = False`); у stacked — только INSIDE_END/CENTER.
`legend.include_in_layout = False`, иначе легенда съедает область
построения; шрифт диаграммы задавать через `chart.font`, а не поэлементно.
