# pptx-report — строгие презентации и аналитические отчёты PPTX

Стиль результата — официально-деловой/научный: без жаргона, без маркетинговых
превосходных степеней, без разговорных формулировок. Слайды насыщенные и
самодостаточные (читаются без докладчика); все числовые данные — в виде
диаграмм, таблиц, KPI-карточек и схем. Нормативные документы скилла:

| Файл | Содержание |
|---|---|
| `references/style-guide.md` | Регистр речи, заголовки-выводы, плотность, числа/даты/типографика, структура отчёта, чек-лист |
| `references/slide-patterns.md` | 10 архетипов слайдов + макеты шаблона ОПИ |
| `references/data-visuals.md` | Выбор и оформление диаграмм, таблиц, KPI, схем |
| `references/brand-templates.md` | Палитры/шрифты двух брендов, правило 60–30–10 |

**Обязательно прочитайте `style-guide.md` до написания первого текста слайда.**

> Если `skill` tool не видит скилл, проверьте установку: он должен лежать
> в `.opencode/skill/pptx-report/` или `~/.config/opencode/skill/pptx-report/`
> (см. README репозитория). До установки читайте `SKILL.md` и `references/`
> напрямую из каталога скилла.

## Маршрутизация по задаче

| Задача | Маршрут |
|---|---|
| Создать отчёт/презентацию с нуля | Маршрут A: `scripts/build_deck.py` по JSON-спецификации |
| Создать в корпоративном шаблоне / максимально похожим на образец | Маршрут B: из шаблона (unzip → дублирование слайдов → правка XML) |
| Изменить существующий .pptx | Маршрут B (точечная правка XML нужных слайдов) |
| Прочитать/разобрать .pptx | `python scripts/extract_text.py deck.pptx [--layouts] [--json]` |

## Зависимости

- Стандартная библиотека Python 3.10+ — маршруты чтения, шаблона, валидации.
- `python-pptx` — только маршрут A: `pip install python-pptx` (если import
  падает). Не устанавливайте ничего остального «на всякий случай».
- `Pillow` — опционально: точное измерение строк для динамических заголовков
  и проверки переполнения. Без него используется эвристика.
- Визуальный QA (опционально): PowerPoint или LibreOffice —
  `scripts/export_images.ps1`.

## Проектор и кегль

Если презентация показывается на проекторе, используйте пресет:

```bash
python scripts/build_deck.py spec.json -o deck.pptx --brand harness --projector --lint
```

- `--projector`: минимальный кегль 14 pt, кегли масштабируются на 1.12.
- `--min-font 14`: явный порог без изменения масштаба.
- `--font-scale 1.15`, `--title-size 28`: точечная настройка.
- `--no-footer`: убрать нижний колонтитул, если он мешает.
- В спеке: `"min_font": 14`, `"projector": true`, `"show_footer": false`,
  `"title_size": 26`, `"source_size": 14`.
- Минимум 14 pt относится ко всем runs, включая source, footer и подписи
  диаграмм. Проверка: `validate_deck.py --min-font 14`.

## Маршрут A — сборка с нуля (build_deck.py)

Бренды: `opi` (отчёт НИР, 10×5,625", сине-зелёная гамма) и `harness`
(аналитика для руководства, 13,33×7,5", тёмно-синий + терракота). Детали —
`references/brand-templates.md`.

1. **Содержание прежде формы.** Соберите фактуру: тезисы, числа, источники.
   Сформулируйте для каждого слайда заголовок-вывод (action title).
   Структуру отчёта возьмите из `style-guide.md` § 5 (принцип пирамиды:
   титул → ключевые положения → … → выводы/рекомендации → источники).
2. **Спецификация.** Напишите `spec.json` (формат — в docstring
   `build_deck.py`; полный пример всех типов слайдов —
   `examples/spec-example.json`; минимальный:
   `python scripts/build_deck.py --example-spec`).
   Типы слайдов: `title, section, summary, content, kpi, chart, table,
   cards, matrix, timeline, closing, refs`. `cards` — 2–4 равные колонки
   с номером, аспектом, пунктами и нижним блоком; `matrix` — матрица
   «строка × колонка» для сравнения слоёв и этапов. Диаграммы — только
   нативные (`kind`: col, col_stacked, bar, bar_stacked, line, area, pie,
   doughnut, scatter). У каждого слайда с данными — поле `source`.
3. **Сборка:**
   ```
   python scripts/build_deck.py spec.json -o report.pptx --brand opi --lint
   python scripts/build_deck.py spec.json -o report.pptx --brand harness --projector --lint
   ```
   `--lint` печатает предупреждения о структуре отчёта — исправьте
   спецификацию и пересоберите.
4. **QA** — см. ниже. Исправления вносите в `spec.json`, не в готовый файл.

### Ограничения Route A

- Нет произвольных схем со стрелками и слоями. Для трёх-четырёх
  смысловых колонок используйте `cards`, для матрицы «слой × этап» —
  `matrix`; для нестандартной графики — Route B.
- Таблицы и таймлайны по умолчанию выравниваются по верху (`align: "top"`),
  чтобы не возникало пустот над короткой таблицей.
- `stat` в `content` и карточки `kpi` имеют авто-высоту; переопределение —
  `stat.height`, `card_height`.
- Заголовок измеряется по шрифту и переносится динамически; если он
  занимает больше двух строк, `--lint` предупредит.
- Диаграмма без `chart.title` не получает авто-заголовок из имени серии.

## Маршрут B — из шаблона / правка существующего

Шаблоны: `templates/rnd-report-opi.pptx` (донор макетов НИР-отчёта),
`templates/exec-wide-harness.pptx` (референс широких слайдов) или файл
пользователя. Все структурные операции — ДО правки текстов.

```
python scripts/from_template.py list    templates/rnd-report-opi.pptx   # слайды + макеты + превью
python scripts/from_template.py layouts templates/rnd-report-opi.pptx   # именованные макеты
python scripts/from_template.py unpack  templates/rnd-report-opi.pptx unpacked/
python scripts/from_template.py duplicate unpacked/ slide2.xml --after slide2.xml
python scripts/from_template.py delete  unpacked/ slide5.xml slide6.xml
python scripts/from_template.py clean   unpacked/
# …правка текста в unpacked/ppt/slides/slideN.xml (см. правила ниже)…
python scripts/from_template.py pack    unpacked/ report.pptx
python scripts/validate_deck.py report.pptx
```

Правила правки XML слайдов:
- Один `<a:p>` на пункт списка; не склеивайте пункты в один абзац.
  Копируйте соседний `<a:pPr>` (отступы/интервалы) и добавляйте `b="1"`
  в `<a:rPr>` для полужирных вводов («Актуальность:», «Источник:»).
- Маркеры наследуются от макета; для переопределения — `<a:buChar>` /
  `<a:buAutoNum>`; никогда не вставляйте литеральный «•» в текст.
- Текст с крайними пробелами — `<a:t xml:space="preserve">`.
- Не переставляйте детей `<p:presentation>`; не правьте XML регулярными
  выражениями «вслепую» — только осознанные точечные замены.
- Дублированный слайд разделяет медиа/диаграммы с исходным по ссылке:
  правка диаграммы на копии меняет оригинал. Нужна независимая диаграмма —
  соберите слайд маршрутом A и вставьте как картинку/таблицу, либо
  скопируйте часть диаграммы вручную вместе с rels.
- Замещайте ВСЁ содержимое шаблона: тексты, подписи авторов, таблицы,
  заметки докладчика (`ppt/notesSlides/`). Остатки чужого проекта —
  дефект (ловится QA-грепом ниже).
- `.potx` распаковывается/пакуется так же; на выходе сохраните расширение.
- Наследие `.ppt`: сначала конвертировать в `.pptx` (LibreOffice/PowerPoint).

## Требования к содержанию (жёсткие)

1. **Без жаргона и разговорного стиля** — нормализуйте формулировки по
   таблице `style-guide.md` § 1. Оценки — только через критерий и число.
2. **Заголовки-выводы**: каждый заголовок слайда — утверждение о результате
   («Трудоёмкость снижена на всех переделах»), не тема («Результаты»).
3. **Плотность**: 2–4 смысловых блока на слайд; списки 3–7 пунктов; пункт —
   законченная мысль. Слайд самодостаточен: отчёт читают без автора.
4. **Данные визуально**: число → диаграмма/таблица/KPI (матрица выбора —
   `data-visuals.md` § 1). У каждого визуала — единицы измерения, подписи
   значений и строка «Источник: …».
5. **Структура отчёта**: титул → ключевые положения (summary) → содержание →
   выводы и рекомендации (closing) → источники (при внешних данных).
   Разделы от 12 слайдов — через разделители (section).
6. **Единообразие**: одна палитра, одна пара шрифтов, один формат дат/единиц/
   округлений на весь документ; чередование архетипов (не >3 одинаковых
   подряд); тёмные титул/разделители/финал, светлое содержание.
7. **Язык по умолчанию — русский**; термины и аббревиатуры — по
   `style-guide.md` § 1 (расшифровка при первом употреблении).

## QA — обязателен перед сдачей

```
# 1. Содержимое: порядок, полнота, остатки шаблона
python scripts/extract_text.py report.pptx
#    grep по мусору и чужому контенту (PowerShell):
#    (python scripts/extract_text.py report.pptx) -match "lorem|TODO|встав|xxx"
#    для шаблона ОПИ также проверьте отсутствие чужих фамилий/названий проектов

# 2. Структура файла (обязательно)
python scripts/validate_deck.py report.pptx            # exit 0 = годен
python scripts/validate_deck.py report.pptx --strict   # при сборке из шаблона

# 2a. Типографика и геометрия (для проектора — обязательно)
python scripts/validate_deck.py report.pptx --strict \
    --min-font 14 --check-overlap --check-bounds --check-overflow
#    --min-font 14          все runs не ниже 14 pt, включая source/footer
#    --check-overlap        пересечения текстовых блоков
#    --check-bounds         выход фигур за границы слайда
#    --check-overflow       оценка переполнения по длине текста и кеглю

# 3. Визуальный контроль (если установлены PowerPoint или LibreOffice)
powershell -ExecutionPolicy Bypass -File scripts/export_images.ps1 -Deck report.pptx -OutDir qa_images
#    просмотрите КАЖДЫЙ слайд свежим взглядом; дефекты по приоритету:
#    а) текст выходит за границы фигуры/слайда (проверять первым);
#    б) наложения элементов, коллизии колонтитула и источника с контентом;
#    в) интервалы < 0,3" между блоками, поля < 0,5"; несоосные колонки;
#    г) низкий контраст (светлый текст на светлом, тёмный на тёмном);
#    д) незаполненные заглушки и остатки шаблона.
```

Первый рендер почти всегда содержит 2–3 реальных дефекта (переполнение,
наложение, несоосность). Найдите, исправьте в источнике (spec.json / XML),
пересоберите, повторно проверьте только изменённые слайды — и остановитесь.
Если PowerPoint/LibreOffice отсутствуют, визуальный QA замените усиленным
текстовым: проверьте длины строк против размеров контейнеров и обязательные
элементы (заголовок, источник, нумерация) по чек-листу `style-guide.md` § 7.

## Типовые ошибки генерации

- Питч-дек вместо отчёта: один тезис на слайд, нет данных, нет источников.
  Отчёт руководству/научный доклад — плотные самодостаточные слайды.
- Заголовки-темы вместо заголовков-выводов.
- Цифры перечислением в тексте вместо диаграммы/таблицы/KPI.
- Жаргон и разговорные обороты («задеплоили», «крутой эффект»).
- Мелкий кегль на проекторе: source/footer 9 pt, таблицы 10,5 pt.
- Таблица или таймлайн, вертикально центрированные на пустом слайде.
- Диаграмма без `chart.title` и с авто-заголовком из имени серии.
- 3D, радужные палитры, более 6 серий/категорий, легенда у одной серии.
- Пустая строка источника у слайда с данными.
- Остатки содержимого шаблона (авторы, названия чужих проектов).
- Правка готового .pptx вместо исправления spec.json/XML-источника.
