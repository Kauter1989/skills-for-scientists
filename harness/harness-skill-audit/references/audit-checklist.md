# Чек-лист аудита библиотеки

Нормативный документ `harness-skill-audit`. Аудит read-only: навык не
исправляет найденное, а фиксирует evidence и рекомендацию.

## 1. Рамка

- Что проверяется: вся библиотека, домен или отдельный навык.
- Дата снимка и корень репозитория.
- Прошлый отчёт — если есть, для тренда.
- Политика severity и порог дублей.

## 2. Инвентаризация

| Проверка | Что фиксируется |
|---|---|
| Каталоги доменов | `dev`, `sci`, `harness`, `reports` |
| Навыки | каталог с `SKILL.md` |
| Владелец | `metadata.domain` или каталог домена |
| Контракт | `metadata.contract` |
| Артефакты | `references/`, `scripts/`, `templates/`, `examples/` |
| Размер | число файлов и строк, если нужно для тренда |

## 3. Структурные проверки

Для навыков с `metadata.contract: harness-skill-template`:

- [ ] `name` совпадает с каталогом;
- [ ] `name` проходит regex и префикс домена;
- [ ] `description` не пуст и короче 1024;
- [ ] все обязательные разделы на месте;
- [ ] `examples/` не пуст;
- [ ] относительные ссылки существуют;
- [ ] Python-скрипты компилируются;
- [ ] нет `TODO`/`{{...}}`;
- [ ] нет имён внутренних проектов и секретов.

Для legacy-навыков без контракта фиксируется одно предупреждение, а не
десяток структурных ошибок: сначала нужно перевести навык на контракт.

## 4. Дубли триггеров

- Сравниваются `description` всех навыков.
- Точное совпадение — `blocker`.
- Сходство ≥ 0,70 — `major`, «возможный дубль», требует решения
  пользователя.
- Порог по умолчанию: **дублей быть не должно**.
- Блокирующий статус и исключение утверждает пользователь.
- Для `blocker` нужен второй проход: открыть оба навыка и сравнить
  сценарии применения.

## 5. Покрытие доменов

Таблица «домен → число навыков». Пустой домен — не дефект сам по себе, но
повод для решения: он запланирован или забыт. Покрытие фиксируется в
JSON для тренда.

## 6. Смысловая выборка

Машинные проверки не видят:

- навык дублирует другой по смыслу при разных словах;
- триггер слишком широкий или слишком узкий;
- пример не воспроизводится;
- процедура противоречит контракту;
- ссылка ведёт на устаревший источник.

Выборка — риск-ориентированная: новые навыки, недавно изменённые,
blocker-находки и навыки без владельца. Для спорной находки — второй
проход.

## 7. Отчёт

- HTML: `docs/audits/<date>.html`.
- JSON: `docs/audits/<date>.json`.
- В отчёте: severity, навык, правило, evidence, рекомендация.
- В JSON: summary, findings, duplicates, coverage — для тренда.
- Отчёт не содержит секретов и персональных данных.

## 8. Завершение

- [ ] Все blocker подтверждены вторым проходом.
- [ ] Для каждой находки есть evidence.
- [ ] Дубли названы явно, решение по ним записано.
- [ ] Отчёт и JSON сохранены.
- [ ] Находки переданы владельцам; исправления — отдельная работа.
- [ ] Следующий аудит запланирован по событию или перед релизом.
