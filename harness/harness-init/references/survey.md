# Опрос для bootstrap

Нормативный документ `harness-init`. Опрос проводится до создания файлов.

## 1. Правила

- Один вопрос — одна тема.
- Нет наводящих формулировок и оценок.
- У каждого вопроса есть значение по умолчанию.
- Ответы сохраняются в `answers.json`, а не теряются в переписке.
- Пользователь может пропустить вопрос; пропуск фиксируется как выбор
  значения по умолчанию.

## 2. Вопросы

| # | Вопрос | Зачем |
|---|---|---|
| 1 | Какой тип работы: разработка, наука, отчётность, смешанный? | домен и стартовые навыки |
| 2 | Какой стек и команды тестов, линтера, сборки? | `profile.yml`, hooks, CI |
| 3 | Какие стартовые задачи: фича, багфикс, релиз, аудит, отчёт, эксперимент? | набор навыков и этапы |
| 4 | Кто работает в репозитории и какие роли нужны? | права и обзоры |
| 5 | Какие ограничения: приватность, безопасность, ревью, CI? | gates и CI |
| 6 | Какие навыки уже есть и какие нужны на старте? | явный выбор |
| 7 | Нужен ли минимальный или расширенный workflow? | объём scaffold |

## 3. Соответствие ответов и навыков

| Условие | Рекомендуется |
|---|---|
| всегда | `harness-skill-template`, `harness-skill-audit` |
| задачи `rules`, `quality`, `feature`, `bugfix` | `harness-rule-to-mechanism` |
| задачи `report`, `release`, `audit` | `dev-pr-report-html` |
| задача `presentation` | `pptx-report` |
| явный список `skills` | используется как есть |

Рекомендуются только **реализованные** навыки. Proposed-навыки попадают в
план как будущие, но не устанавливаются.

## 4. Формат ответов

```json
{
  "project": "example-service",
  "domain": "dev",
  "stack": "python",
  "default_branch": "main",
  "workflow": "minimal",
  "ci": "github",
  "commands": {
    "test": "pytest -q",
    "lint": "ruff check .",
    "build": ""
  },
  "roles": ["developer", "reviewer"],
  "tasks": ["feature", "bugfix", "report"],
  "constraints": ["private"],
  "skills": []
}
```

Пустой `skills` означает «рекомендовать по ответам».

## 5. Утверждение

После опроса собирается `bootstrap-plan.html`:

- ответы и выбранный workflow;
- стартовые навыки и причины;
- этапы;
- команды;
- список файлов;
- статус `draft` → `approved`.

`apply` не запускается, пока статус не `approved`.

## 6. Ошибки опроса

- спрашивать всё сразу без значений по умолчанию;
- рекомендовать proposed-навык как готовый;
- скрывать, какие файлы будут созданы;
- считать молчание согласием;
- начинать scaffold до утверждения.
