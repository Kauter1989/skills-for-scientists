# harness-init — единая точка входа и bootstrap

Навык — точка входа для построения харнесса. Он задаёт вопросы пользователю,
подбирает стартовые навыки, собирает HTML-план workflow и создаёт файлы
только после `approved`. Если пользователь не знает, какой навык или маршрут
ему нужен, начинать нужно здесь.

## С чего начать

| Что нужно | Куда идти |
|---|---|
| Новый проект, репозиторий или «не знаю, с чего начать» | `harness-init` — опрос и план |
| Новый проект с разработкой и SDD | отдельная команда **`/dev-spec-chain`** |
| Новый навык в библиотеку | `harness-skill-template` → research/review → `harness-skill-audit` → PR |
| Правило превратить в проверку | `harness-rule-to-mechanism` |
| Аудит библиотеки | `harness-skill-audit` |
| Настройка обработки дефектов | `dev-bug-processing` |
| Научный дайджест литературы | `sci-literature-news` |
| HTML-отчёт или презентация | `dev-pr-report-html` / `pptx-report` |

`harness-init` **не настраивает SDD сам**. Если проект предполагает
разработку, он фиксирует специфику и говорит пользователю, что весь
spec-driven workflow настраивается отдельной командой **`/dev-spec-chain`**.
Нельзя выдавать bootstrap-план за готовый SDD.

Нормативные документы:

| Файл | Содержание |
|---|---|
| `references/survey.md` | вопросы опроса и правила формулировок |
| `references/bootstrap-checklist.md` | минимальный состав bootstrap |
| `templates/bootstrap-plan.html` | форма плана на утверждение |
| `scripts/init_repo.py` | survey, plan, approve, apply |
| `scripts/check_bootstrap.py` | проверка результата |

> Если `skill` tool не видит навык, положите каталог в
> `.opencode/skill/harness-init/` или
> `~/.config/opencode/skill/harness-init/`.

## Когда применять

- новый репозиторий или проект без процесса;
- нужно понять, какой навык или маршрут нужен для научной работы с данными и
  отчётами;
- проект предполагает разработку, и нужно зафиксировать его специфику до
  настройки SDD;
- пользователь хочет дополнить библиотеку навыков и не знает правильный
  порядок;
- нужно перенести процесс в существующий репозиторий без перезаписи;
- нужно выбрать стартовый набор навыков под задачи;
- нужен утверждаемый workflow для команды.

## Когда не применять

- репозиторий уже настроен и проходит `check_bootstrap.py`;
- нужен только новый навык — это `harness-skill-template`;
- нужен только аудит библиотеки — это `harness-skill-audit`;
- нужно настроить только SDD — это отдельная команда `/dev-spec-chain`;
- нужна оценка навыка — это `harness-skill-eval` (deferred).

## Вход

- путь к новому или существующему репозиторию;
- ответы пользователя:
  - научная работа с данными и отчётами: анализ, эксперимент, литература,
    датасет, визуализация; форматы, объём и чувствительность данных;
    результаты — статья, HTML, PPTX, dashboard, датасет; воспроизводимость;
  - специфика разработки: greenfield/brownfield, стек, тип продукта,
    критичность, интеграции, deployment; нужен ли SDD;
  - пополнение библиотеки: новый навык, улучшение существующего или ничего;
- выбранный workflow: минимальный или расширенный;
- решение по CI и перезаписи.

## Процедура

1. **Провести опрос.** Задать вопросы из `references/survey.md` тремя
   блоками: научные данные и отчёты, разработка, пополнение библиотеки.
   Сохранить ответы в `answers.json`.

   ```bash
   python scripts/init_repo.py survey --out answers.json
   ```

2. **Определить маршрут.** По ответам:
   - научная работа и отчёты → рекомендовать `sci-literature-news`,
     `dev-pr-report-html`, `pptx-report`;
   - разработка → зафиксировать greenfield/brownfield и специфику, но
     **не настраивать SDD внутри bootstrap**: указать отдельную команду
     `/dev-spec-chain`;
   - пополнение библиотеки → объяснить путь `harness-skill-template` →
     research/review → `harness-skill-audit` → PR;
   - если пользователь просит только новый навык или только SDD, не
     запускать полный bootstrap, а перейти в соответствующий навык/команду.

3. **Собрать план.** Сгенерировать `bootstrap-plan.html` и JSON:

   ```bash
   python scripts/init_repo.py plan --root . \
     --answers answers.json \
     --out bootstrap-plan.html \
     --json bootstrap-plan.json
   ```

4. **Показать план пользователю.** В плане: профиль научной работы и
   разработки, маршрут, стартовые навыки, этапы workflow, команды и список
   создаваемых файлов. Отдельно должно быть видно, что SDD настраивается
   командой `/dev-spec-chain`.
5. **Получить `approved`.** Только после явного решения:

   ```bash
   python scripts/init_repo.py approve \
     --plan bootstrap-plan.html --json bootstrap-plan.json
   ```

6. **Создать файлы.** `apply` откажется работать без `approved`; по
   умолчанию существующие файлы не перезаписываются.

   ```bash
   python scripts/init_repo.py apply --root . --plan-json bootstrap-plan.json
   ```

7. **Проверить bootstrap.**

   ```bash
   python scripts/check_bootstrap.py --root .
   ```

## Выход

- `answers.json` — ответы опроса, включая научную работу, специфику
  разработки и решение по библиотеке;
- `bootstrap-plan.html` — профиль работы, маршрут, workflow и набор навыков
  на утверждение;
- `bootstrap-plan.json` — статус, данные плана и маршрут
  `sdd: /dev-spec-chain`;
- `profile.yml`, `AGENTS.md`, `docs/`, `.pre-commit-config.yaml`, CI;
- `bootstrap-report.md` — что создано и что пропущено.

## Пополнение библиотеки навыков

Если пользователь хочет добавить навык в эту библиотеку, объяснить порядок:

1. **Проверить, нет ли дубля.** `harness-skill-audit` и таблица триггеров;
   новый навык не должен повторять существующий.
2. **Research Gate.** Не менее трёх GitHub-аналогов и двух научных или
   официальных источников; результат — `docs/research/<skill>.md`.
3. **Review Gate.** `docs/reviews/<skill>.html` со статусом `approved`.
4. **Implementation Gate.** `harness-skill-template`: каталог, `SKILL.md`,
   `references/`, `scripts/`, `templates/`, `examples/`.
5. **Verification Gate.** Пример воспроизводится, валидатор проходит, HTML
   без сети, ссылки живые.
6. **PR Gate.** Ветка `feature/<skill>`, PR со ссылками на research, review
   и вывод валидатора; merge только после проверок.

Нельзя добавлять навык «по описанию в чате» без research и review. Если
пользователь хочет изменить существующий навык, сначала прочитать его
`SKILL.md`, `references/` и `examples/`, затем следовать тем же гейтам.

## Доказательства

- `bootstrap-plan.html` содержит статус `approved` до scaffold;
- `apply` отказывается работать со статусом `draft`;
- `check_bootstrap.py` проходит на созданном репозитории;
- повторный `apply` не перезаписывает файлы без `--force`;
- в плане перечислены только реализованные навыки.

## Границы

- Не устанавливает зависимости и не выбирает стек.
- Не настраивает SDD: для этого есть отдельная команда `/dev-spec-chain`.
- Не создаёт навык за `harness-skill-template` и не заменяет research/review.
- Не делает commit, push и PR.
- Не перезаписывает существующие файлы без `--force`.
- Не рекомендует proposed-навыки как установленные.
- Не заменяет ревью плана пользователем.

## Типовые ошибки

- запуск `apply` без `approved`;
- обещание, что bootstrap настроит SDD (это делает `/dev-spec-chain`);
- пропуск вопросов о научных данных, отчётах и специфике разработки;
- рекомендация proposed-навыка как готового;
- перезапись `AGENTS.md` без подтверждения;
- пустая команда тестов, замаскированная под проверку;
- план без списка создаваемых файлов и без маршрута;
- добавление навыка в библиотеку без research/review;
- `check_bootstrap.py` не запускался.

## QA

- [ ] опрос проведён по трём блокам, ответы сохранены;
- [ ] зафиксированы научная работа, данные, отчёты и воспроизводимость;
- [ ] для разработки зафиксированы greenfield/brownfield и специфика;
- [ ] пользователю явно названа команда `/dev-spec-chain` для SDD;
- [ ] решение по пополнению библиотеки зафиксировано;
- [ ] в плане есть маршрут, навыки, этапы, команды и файлы;
- [ ] план утверждён пользователем;
- [ ] `apply` не перезаписал существующее;
- [ ] `check_bootstrap.py` проходит;
- [ ] `profile.yml` содержит команды и навыки;
- [ ] CI создан только если выбран;
- [ ] нет секретов и проектных данных в шаблонах.
