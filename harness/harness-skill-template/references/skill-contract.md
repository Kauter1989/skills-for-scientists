# Контракт навыка

Нормативный документ `harness-skill-template`. Определяет, из чего состоит
навык, какие поля обязательны и что проверяет валидатор.

## 1. Каталог

```
<domain>/<skill-name>/
├── SKILL.md          обязательно
├── references/       нормативы, формулы, схемы
├── scripts/          детерминированный сбор и проверка
├── templates/        форма результата
└── examples/         хотя бы один пример входа и выхода
```

- `SKILL.md` — единственная точка входа; всё остальное загружается по
  необходимости.
- `references/` и `scripts/` не обязательны, но если на них ссылаются,
  файлы обязаны существовать.
- `examples/` обязателен: без примера навык не считается проверенным.
- Имя каталога совпадает с `name` во frontmatter.

## 2. Frontmatter

```yaml
---
name: harness-example
description: >-
  Что делает навык и когда его применять. Use when ...
license: Apache-2.0
metadata:
  domain: harness
  contract: harness-skill-template
  version: "0.1.0"
---
```

| Поле | Обязательно | Ограничение |
|---|---|---|
| `name` | да | 1–64 символа, `a-z`, `0-9`, `-`; без ведущего/конечного дефиса и `--`; совпадает с каталогом |
| `description` | да | 1–1024 символа; что делает и когда применять; ключевые слова для поиска |
| `license` | нет | имя лицензии или ссылка на файл |
| `compatibility` | нет | до 500 символов: окружение, зависимости, сеть |
| `metadata` | нет | произвольные пары строк |
| `allowed-tools` | нет | экспериментальное поле; перечисление инструментов |

Локальный маркер `metadata.contract: harness-skill-template` нужен, чтобы
`validate_skill.py --all` проверял только навыки этого контракта. Навыки без
маркера считаются legacy и пропускаются с предупреждением.

## 3. Описание

Хорошее описание отвечает на два вопроса:

1. **Что делает** — одно предложение с глаголом.
2. **Когда применять** — условия, симптомы задачи, ключевые слова.

Плохо: «Инструмент для работы с отчётами».
Хорошо: «Собирает HTML-отчёт об изменениях фичи: метрики, доказательства,
решения. Use when closing a feature or milestone and a review needs numbers
instead of a diff. Trigger on: отчёт по фиче, milestone report».

Правила:

- не перечислять внутренние шаги вместо условия применения;
- не дублировать имя навыка;
- включать русские и английские триггеры, если библиотека двуязычная;
- не обещать больше, чем навык делает.

## 4. Обязательные разделы `SKILL.md`

Заголовки уровня `##`, регистр не важен.

| Раздел | Что должно быть |
|---|---|
| `Когда применять` | 3–7 конкретных ситуаций |
| `Когда не применять` | границы и соседние навыки |
| `Вход` | что автор/пользователь обязан передать |
| `Процедура` | упорядоченные шаги, команды, точки решений |
| `Выход` | артефакты и их формат |
| `Доказательства` | как проверить, что выход настоящий |
| `Границы` | что навык не делает и почему |
| `Типовые ошибки` | как выглядит неправильное применение |
| `QA` | чек-лист перед сдачей |

Дополнительные разделы допустимы: `Пример`, `Файлы`, `История`,
`Метрики`. Они не заменяют обязательные.

## 5. Домены и префиксы

| Папка | Префикс имени | Пример |
|---|---|---|
| `dev/` | `dev-` | `dev-ship` |
| `sci/` | `sci-` | `sci-stats-report` |
| `harness/` | `harness-` | `harness-skill-template` |
| `reports/` | без префикса | `pptx-report` |

Валидатор проверяет префикс, если навык лежит в доменной папке.

## 6. Артефакты

- `references/` — нормативы, формулы, схемы данных. Документ не должен
  дублировать `SKILL.md`.
- `scripts/` — только детерминированные операции: сбор, проверка,
  генерация. Скрипт обязан запускаться без сети, если не указано иное.
- `templates/` — форма результата, которую заполняет пользователь.
- `examples/` — эталонный вход и выход. Секреты, токены и внутренние имена
  проектов запрещены.

## 7. Проверка

```bash
python scripts/validate_skill.py <domain>/<skill-name> --root <repo>
python scripts/validate_skill.py --all --root <repo>
python scripts/validate_skill.py <path> --json
```

Валидатор проверяет:

- каталог и `SKILL.md`;
- frontmatter и ограничения `name`/`description`;
- обязательные разделы;
- относительные ссылки;
- непустой `examples/`;
- компиляцию Python-скриптов;
- предупреждения о проектных именах и секретах.

Он **не** проверяет смысл, качество источников и пользу навыка.

## 8. Definition of Done

- [ ] Research Gate пройден по `AGENTS.md`;
- [ ] review HTML имеет статус `approved`;
- [ ] `validate_skill.py` завершился без ошибок;
- [ ] пример воспроизводится;
- [ ] обновлены карта и README;
- [ ] нет проектных имён и секретов;
- [ ] ветка запушена и PR открыт.

## 9. Антипаттерны

- навык-эссе без входа и выхода;
- описание «умеет всё»;
- раздел «Границы» пуст;
- пример только в тексте, без файла;
- скрипт, который меняет репозиторий без подтверждения;
- копирование чужого кода без проверки лицензии;
- валидатор, который проверяет только наличие файлов и создаёт ложную
  уверенность.
