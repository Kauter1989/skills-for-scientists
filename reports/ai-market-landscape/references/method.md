# Методика анализа рынка

Нормативный документ `ai-market-landscape`. Определяет, как из снимка
компаний получается динамика по домену, услугам и ПАК и как формулируется
разница рынков РФ и мира.

## 1. Что измеряется

| Объект | Описание | Источник данных |
|---|---|---|
| Компания | юридическое или продуктовое лицо, публикующее ИИ-продукт | сайт компании, каталог, публикация |
| Когорта `RF` | штаб-квартира в РФ | курируемый реестр, ЕГРЮЛ, сайт |
| Когорта `WORLD` | штаб-квартира вне РФ | открытый каталог моделей, сайт |
| Снимок | набор компаний с датой, URL и меткой качества | `companies-YYYY-MM-DD.json` |

Когорты считаются **независимо**. Сравнивать их можно только по долям: число
компаний на рынке РФ и мира отличается на порядок, и абсолютная разность
ничего не значит (Ильина и др., 2019; Santarlasci и др., 2025).

## 2. Порядок работы

```
профиль -> сбор -> курирование -> анализ -> отчёт -> проверка
```

1. **Профиль.** `profile.py init` создаёт `.ai-market-landscape/landscape.md`
   с когортами, таксономией и периодом. Таксономия объявляется до сбора:
   иначе её невозможно отличить от подгонки под результат (Alex, 2021).
2. **Сбор.** `collect.py --source openrouter` даёт когорту мира по факту
   публикации моделей; `--source habr` даёт сигналы по компаниям РФ.
   Собранные записи помечаются `needsReview: true`.
3. **Курирование.** Аналитик описывает роль, домен, услуги и ПАК у тех
   записей, которые нужны для выводов, и снимает `needsReview`. Каждое поле
   получает метку качества.
4. **Анализ.** `analyze.py` проверяет таксономию, считает метрики и пробелы.
   Записи с `needsReview` в доли не входят.
5. **Отчёт.** `build_report.py` собирает три независимых блока: Россия, Мир,
   разница рынков.
6. **Проверка.** `check_report.py` подтверждает автономность и наличие
   источников.

## 3. Динамика

Динамика требует **минимум двух снимков одной методологии**. Один снимок даёт
только состояние: в этом случае `changes.from = null`, а любая метрика
прироста получает `missing` (Shen и др., 2025: сравнение когорт корректно
только при одинаковых правилах отбора).

Три оси динамики:

| Ось | Что показывает | Ограничение |
|---|---|---|
| Домен | сдвиг приложений: медицина, финансы, промышленность и т. д. | домен присваивается по публичным материалам, это оценка |
| Спектр услуг | сдвиг от разработки к интеграции, поддержке и обучению | у автоматически собранных записей услуги — значение по умолчанию |
| ПАК | сдвиг к аппаратно-программным комплексам | класс ПАК подтверждается только описанием линейки |

## 4. Разница рынков

Разница считается по долям внутри когорты:

```
gap = share_WORLD(key) - share_RF(key)
```

Правила:

- доля считается только при не менее 10 компаниях в каждой когорте, иначе
  `missing` (маленькая выборка даёт скачки на одну компанию);
- пробел фиксируется, когда в РФ **0** компаний, а в мире **не менее 3**;
- «нет данных в источнике» никогда не равно «нет компании в РФ»: пустая
  когорта — это `missing`, а не ноль.

Отдельно выводится разница ролей: какие роли (`developer`, `integrator`)
есть в мире и не встречаются в РФ.

## 5. Что не считается

- Ёмкость рынка в деньгах: для этого нужен официальный финансовый источник,
  которого у навыка нет.
- Прогноз выручки и капитализации.
- Оценка качества компаний: навык описывает структуру рынка, а не ранжирует
  игроков.
