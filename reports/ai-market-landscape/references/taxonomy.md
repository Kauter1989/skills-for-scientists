# Таксономия осей

Нормативный документ `ai-market-landscape`. Таксономия объявляется до сбора и
меняется только осознанно: изменение набора значений ломает сравнимость
снимков.

## 1. Роли

| Значение | Определение | Как подтверждается |
|---|---|---|
| `developer` | разрабатывает собственную ИИ-модель, платформу или продукт с определяющим ИИ-компонентом | каталог моделей, сайт, публикация |
| `integrator` | внедряет, дорабатывает и поставляет чужие или собственные ИИ-решения | сайт, описание линейки услуг |

Компания может иметь обе роли. Наличие только роли `integrator` означает,
что собственная разработка не подтверждена.

## 2. Доменные области

Домен — сфера применения, а не технология. Компания может иметь несколько
доменов.

| Код | Область | Примеры применения |
|---|---|---|
| `med` | медицина | диагностика, клинические решения, медзаписи |
| `fin` | финансы | скоринг, риск, торговые системы |
| `industrial` | промышленность | контроль качества, предиктивное обслуживание, робототехника |
| `security` | безопасность | кибербезопасность, биометрия, видеонаблюдение |
| `education` | образование | адаптивное обучение, аналитика успеваемости |
| `media` | медиа и контент | генерация текста, изображения, видео, речь |
| `agro` | агро | урожайность, мониторинг полей |
| `public` | госсектор | документооборот, аналитика для органов власти |
| `mobility` | транспорт | беспилотное вождение, логистика, карты |

Если домен не подтверждён источником, поле остаётся пустым (`missing`). Отчёт
показывает такие компании, но их домен не входит в доли.

## 3. Спектр услуг

| Код | Услуга | Отличие от соседней |
|---|---|---|
| `consulting` | консалтинг | оценка задачи без поставки системы |
| `integration` | интеграция | внедрение в существующие процессы |
| `development` | разработка | создание модели, платформы или продукта |
| `licensing` | лицензирование | передача права использования модели или API |
| `mlops` | MLOps | эксплуатация, мониторинг, переобучение моделей |
| `data_services` | работа с данными | разметка, сбор, подготовка датасетов |
| `support` | поддержка | сопровождение после запуска |
| `training` | обучение | подготовка персонала заказчика |
| `hardware` | аппаратные поставки | поставка оборудования, в том числе в составе ПАК |

У записей, собранных автоматически, заполнены `development` и `licensing`:
это значение по умолчанию сборщика и оно явно помечается в отчёте.

## 4. ПАК

| Код | Класс | Признак |
|---|---|---|
| `none` | без ПАК | продукт поставляется как сервис или ПО |
| `ai_component` | ИИ-компонент в ПАК | ИИ встроен в чужое или своё оборудование |
| `ai_system` | ИИ-система | система, где ИИ определяет функции |
| `ai_software_package` | программно-аппаратный комплекс | комплекс поставлен и как ПО, и как аппаратура |

Правило: класс ПАК подтверждается описанием поставки, а не наличием слова
«платформа» в маркетинговых материалах. Если поставка не описана —
`none` не ставится молча, поле остаётся `missing`-подобным и помечается
пояснением в `caveats`.

## 5. Модель поставки

| Код | Поставка |
|---|---|
| `api` | облачный API |
| `on_prem` | установка на инфраструктуре заказчика |
| `saas` | подписка на сервис |
| `pak` | поставка в составе комплекса |
| `none` | поставка не описана |

## 6. Изменение таксономии

- Добавление значения допустимо между снимками, но снимки с разными наборами
  осей сравниваются только по общим значениям.
- Удаление или переименование значения требует нового `schemaVersion` и
  пересборки анализа; старые снимки не переписываются.
