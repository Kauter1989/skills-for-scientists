# ai-market-landscape — динамика ИИ-рынка РФ и мира

Навык ведёт профиль рынка, собирает снимок компаний из открытых источников,
курирует роли и домены, считает динамику по трём осям и собирает автономный
HTML-отчёт с тремя независимыми блоками: Россия, мир без России и разница
рынков.

Домен — отчётность: каталог `reports/ai-market-landscape/`.

## Когда применять

- нужен ответ на вопрос «как развивается ИИ-рынок в РФ по сравнению с миром»;
- нужно разделить компании на разработчиков и интеграторов;
- нужна динамика по доменным областям: медицина, финансы, промышленность и др.;
- нужен спектр услуг: консалтинг, интеграция, разработка, лицензирование, MLOps;
- нужен срез по программно-аппаратным комплексам и ИИ-компонентам в них;
- нужно показать, какие сегменты есть в мире и отсутствуют в РФ, с порогом и
  источником;
- нужен повторяемый отчёт: тот же профиль, новый снимок, сравниваемая таблица.

## Когда не применять

- для оценки отдельной компании, её финансов и менеджмента;
- для ёмкости рынка в рублях и долларах — нет официального финансового
  источника;
- для прогноза выручки и капитализации;
- для научного обзора литературы — это `sci-literature-news`;
- для презентации PPTX — это `pptx-report`;
- для юридической проверки контрагента и выгрузки из закрытых баз.

## Вход

- профиль `.ai-market-landscape/landscape.md` с когортами, таксономией и
  периодом (шаблон: [templates/landscape.md](templates/landscape.md));
- при повторном запуске — предыдущий снимок `companies-YYYY-MM-DD.json`;
- курируемый реестр компаний с URL, если нужны роли и домены, а не только
  факт публикации;
- решённые пороги: минимум компаний для доли (по умолчанию 10) и порог
  пробела (0 в РФ и 3 в мире).

## Процедура

### 1. Определить рабочий каталог

Все данные лежат в `.ai-market-landscape/` текущего проекта:

```text
.ai-market-landscape/
├── landscape.md                 профиль
├── companies-2026-11-06.json    снимок
├── analysis.json                анализ
└── report.html                  отчёт
```

### 2. Создать или показать профиль

```bash
python scripts/profile.py --file .ai-market-landscape/landscape.md init --name "ИИ-рынок"
python scripts/profile.py --file .ai-market-landscape/landscape.md check
python scripts/profile.py --file .ai-market-landscape/landscape.md show
```

Таксономия объявляется здесь и до сбора. Если пользователь просит новую ось,
это изменение профиля, а не правка отчёта.

### 3. Согласовать профиль с пользователем

Показать период, когорты, набор осей и пороги. Получить подтверждение и
зафиксировать его:

```bash
python scripts/profile.py --file .ai-market-landscape/landscape.md confirm
```

До `confirm` сбор не запускать: иначе методология меняется после результата.

### 4. Собрать снимок

```bash
python scripts/collect.py --source openrouter --out .ai-market-landscape/companies-2026-11-06.json
python scripts/collect.py --source habr --query "GigaChat Сбер" --query "YandexGPT" \
  --out .ai-market-landscape/signals-rf.json
python scripts/collect.py --in .ai-market-landscape/companies-2026-11-06.json \
  --merge .ai-market-landscape/signals-rf.json --merge curated.json \
  --check-sites --out .ai-market-landscape/companies-2026-11-06.json
```

Что происходит:

- `openrouter` даёт организации мира, публикующие модели, и год первой модели;
- `habr` даёт сигналы по компаниям РФ: публикации подтверждают активность,
  но не роль на рынке;
- `--check-sites` проверяет доступность сайтов и записывает `siteStatus`;
- собранные автоматически записи получают `needsReview: true` и не входят в
  доли;
- недоступный источник не превращается в ноль: запись получает `missing`.

Если источника нет совсем, честный результат — `missing` и предупреждение,
а не «в РФ этого нет».

### 5. Курировать записи, которые нужны для выводов

Для каждой компании, участвующей в долях, заполнить:

- `roles` — `developer` и/или `integrator`;
- `domains` — одна или несколько областей;
- `services` — от консультации до аппаратных поставок;
- `pak` — класс программно-аппаратного комплекса;
- `evidence` — URL и дата;
- `quality` — `measured`, `estimated` или `expert`;
- снять `needsReview`, когда роль подтверждена.

Правила курирования: [references/sources.md](references/sources.md).

### 6. Рассчитать анализ

```bash
python scripts/analyze.py .ai-market-landscape/companies-2026-11-06.json \
  --profile .ai-market-landscape/landscape.md \
  -o .ai-market-landscape/analysis.json --strict

# динамика: передать предыдущий снимок
python scripts/analyze.py .ai-market-landscape/companies-2026-11-06.json \
  --previous .ai-market-landscape/companies-2025-11-06.json \
  -o .ai-market-landscape/analysis.json --strict
```

`--strict` требует у каждой компании `evidence` с URL и датой, а таксономию
проверяет всегда: значение вне набора осей — ошибка, а не «новая категория».

### 7. Собрать отчёт

```bash
python scripts/build_report.py \
  --analysis .ai-market-landscape/analysis.json \
  --companies .ai-market-landscape/companies-2026-11-06.json \
  -o .ai-market-landscape/report.html --strict
```

### 8. Проверить и отдать

```bash
python scripts/check_report.py .ai-market-landscape/report.html
python scripts/test_example.py
```

`test_example.py` работает офлайн на примере и проверяет инварианты
методики: метки качества у метрик, отсутствие непроверенных записей в долях,
порог пробела, блоки отчёта и отсутствие внешних ресурсов.

Отдать пользователю `report.html`, `analysis.json` и снимок. В ответе назвать:
дату снимка, число компаний в каждой когорте, число записей, ожидающих
проверки, и области, где данных нет.

## Выход

| Артефакт | Содержание |
|---|---|
| `landscape.md` | профиль: когорты, таксономия, период, пороги |
| `companies-YYYY-MM-DD.json` | снимок с `evidence`, `quality`, `siteStatus` |
| `analysis.json` | метрики когорт, динамика, GAP, пробелы, ожидающие проверки |
| `report.html` | автономная страница: Россия, Мир, Разница рынков, Методика |

## Доказательства

Отчёт считается настоящим, когда выполнено всё:

- `check_report.py` вернул `[ok]` и `external resources: none`;
- у каждой метрики видна метка качества: измерено, расчёт, оценка, экспертно
  или нет данных;
- у каждой компании в таблице есть URL или запись `missing`;
- число записей, ожидающих проверки, названо в отчёте и в ответе;
- области без данных показаны как «нет данных», а не как ноль;
- `analysis.json` воспроизводится командой из шага 6 на том же снимке.

Метрики и их качество: [references/metrics.md](references/metrics.md).

## Границы

- Не оценивает качество и перспективы отдельных компаний.
- Не измеряет ёмкость рынка в деньгах и не строит прогнозы.
- Не гарантирует полный охват рынка: каталоги неполны, а отбор записей —
  классификация с ошибками (Erana, Finlayson, 2024).
- Не заменяет юридическую проверку контрагента.
- Не собирает персональные данные.
- Не парсит закрытые коммерческие базы.
- Пороги доли и пробела — продуктовое решение автора, а не научный факт:
  при изменении порога меняется отчёт, а не методика скрыто.
- Разница рынков — разница **долей**, а не разница числа компаний.

## Типовые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| в РФ «всё отсутствует» | когорта РФ пуста | собрать курируемый реестр; пустое не равно нулю |
| доли GAP равны нулю у всех | когорта меньше порога | набрать компании или повысить прозрачность: оставить `missing` |
| ошибка «роль вне таксономии» | новое значение без профиля | согласовать таксономию в профиле |
| повторяющийся id | слияние двух вендоров в одного | проверить `aliases`; id задаётся вручную |
| все компании в «ждут проверки» | роли не проставлены | курировать записи перед выводами |
| отчёт без источников | компания без `site` и `evidence` | добавить URL или пометить `missing` |
| внешние ресурсы в HTML | добавлен CDN | вернуть встроенный CSS |

## QA

- [ ] профиль создан, `check` проходит, `Last confirmed` обновлён;
- [ ] период и пороги показаны пользователю до сбора;
- [ ] снимок содержит `snapshotDate` и дату обращения у каждого `evidence`;
- [ ] у каждой компании есть `evidence` с URL и датой;
- [ ] записи с `needsReview` не попали в доли и перечислены в отчёте;
- [ ] `analyze.py --strict` завершился без ошибок;
- [ ] `build_report.py --strict` собрал отчёт;
- [ ] `check_report.py` вернул `[ok]`, внешних ресурсов нет;
- [ ] в отчёте есть блоки «Россия», «Мир (без РФ)», «Разница рынков», «Методика»;
- [ ] области без данных показаны как «нет данных»;
- [ ] для динамики передан предыдущий снимок, иначе `DD_YEAR` = «нет данных»;
- [ ] выводы отделяют измеренное от оценки;
- [ ] персональных данных нет.

```bash
cd reports/ai-market-landscape

```

каталог моделей меняется каждый день.
