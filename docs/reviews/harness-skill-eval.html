01

Проблема и границы

«Работает» обычно означает один удачный запуск. Без baseline не видно прироста, без повторов — дисперсии, без фиксации модели и промпта — воспроизводимости, без стоимости — цены навыка. Оценка превращается во впечатление.

Входит в задачу

  • набор задач, baseline, повторы, метрики триггера и качества, стоимость, отчёт и решение по навыку.

Не входит

  • аудит структуры библиотеки, разработка навыка и создание механизмов.

04

Синтез и предлагаемый дизайн

Аналоги сходятся на схеме task → run → score → report, но оценивают модели и промпты, а не навык. Исследования добавляют: формат промпта влияет на результат, один запуск нестабилен, воспроизводимость требует фиксации окружения и логов. Предлагается task-specific протокол с baseline, повторами и явными метриками.

Набор задач→ Baseline и skill→ Повторы и метрики→ Отчёт и решение

Вход

Навык, 5 positive / 5 negative / 3 edge задач, модель и температура, бюджет.

Выход

docs/evals/<skill>/<date>.html, JSON результатов, решение keep/revise/retire.

Артефакты навыка

  • SKILL.md — триггеры, процедура, границы
  • references/ — протокол, схема результатов, метрики
  • scripts/ — сводка результатов и проверка воспроизводимости
  • examples/ — набор задач и отчёт с baseline

06

Метрики и план проверки

Trigger precision / recall — ≥ 0,8 на наборе Pass rate против baseline — прирост ≥ 10 п.п. Разброс между повторами — ≤ 10 п.п.
  1. Baseline и skill запускаются на одном наборе задач и одной конфигурации.
  2. Два повтора дают сопоставимый результат; отклонение записано.
  3. Отчёт воспроизводится из JSON без ручных правок.
