01

Проблема и границы

Пользователь состоит во многих чатах Пачки. Чтобы понять, что сдвинулось по проектам, где блокеры и кто перестал писать, приходится вручную открывать каждый чат и держать в голове историю. Официальный MCP даёт доступ к методам API, но не собирает из них отчёт, не хранит исключения и не проверяет права до сохранения задачи.

Входит в задачу

  • все чаты пользователя, доступные токену;
  • новые сообщения за окно и цитаты-доказательства;
  • прогресс, статус и блокеры по проектам;
  • активность участников и молчание более 2 дней;
  • .pachca/exclusions.md для исключений из диаграммы;
  • .pachca/tasks.md для задач по каналу;
  • preflight прав и повторная проверка перед запуском;
  • один HTML-файл без сети и CDN.

Не входит

  • оценка сотрудников и рейтинги;
  • автоматическая отправка сообщений без задачи;
  • обход скоупов, ролей и закрытых чатов;
  • замена аналитики Пачки и экспорта;
  • гарантия истинности смыслового анализа блокеров;
  • хранение токена в отчёте или репозитории.

04

Синтез и предлагаемый дизайн

Отчёт разделяет измерение и интерпретацию. Плагин измеряет: собирает сообщения, считает активность, проверяет права, рендерит HTML. Модель интерпретирует: определяет прогресс, статус и блокеры по новым сообщениям, но обязана приложить ID сообщений-доказательств. Неподтверждённый вывод получает низкое качество и предупреждение, а не выдаётся за факт.

MCP / REST→snapshot.json→analysis.json + exclusions.md + tasks.md→report.html

Вход

Токен Пачки в PACHCA_TOKEN или OAuth-подключение MCP; окно дат; каталог состояния .pachca/; при необходимости — готовый snapshot и analysis.

Выход

.pachca/reports/pachca-report-YYYY-MM-DD.html, snapshots/*.json, exclusions.md, projects.md, tasks.md, результаты задач.

Процедура

  1. Связь. Плагин добавляет MCP-сервер pachca (OAuth или Bearer из env). pachca_status показывает состояние, скоупы и доступные чаты.
  2. Сбор. pachca.collect читает все чаты пользователя, сообщения с курсорной пагинацией, треды, участников и пользователей; пишет snapshot и обновляет состояние.
  3. Анализ. Агент по новым сообщениям заполняет analysis.json: проект, статус, прогресс, блокеры с ID-доказательствами, следующие шаги, уверенность.
  4. Активность. Плагин считает сообщения по участникам, последнее сообщение и дни молчания; исключения из exclusions.md убираются из диаграммы, но остаются в отдельной панели.
  5. Рендер. pachca.report валидирует цитаты и пишет автономный HTML с фильтрами, KPI, карточками проектов и диаграммой.
  6. Задачи. pachca.tasks add проверяет канал, скоупы, роль, тариф и доступ; при провале задача не сохраняется. check перепроверяет, run выполняет детерминированные задачи или готовит контекст для модели.

Артефакты

  • SKILL.md — триггеры, процедура, границы, QA.
  • references/pachca-api.md — методы, скоупы, роли, лимиты.
  • references/report-schema.md — snapshot/analysis, формулы, качество данных.
  • references/tasks.md — действия, preflight, запуск.
  • scripts/check_report.py и scripts/validate_analysis.py — независимые проверки.
  • templates/ и examples/example-report.html — форма и эталон.
  • Плагин opencode-plugins/pachca/ — MCP-регистрация, инструменты, тесты.

06

Метрики и план проверки

Покрытие чатов — прочитано / доступно Цитаты — доля проектов с evidence ID Молчащие — порог 2 дня, настраивается Preflight — 100% задач до сохранения
  1. Прогнать node test/run-tests.mjs: snapshot, активность, исключения, задачи, HTML.
  2. Сгенерировать examples/example-report.html и проверить python scripts/check_report.py.
  3. Проверить python scripts/validate_analysis.py на примере и на повреждённом analysis.
  4. Проверить, что в HTML нет внешних script, link, @import, fetch и CDN.
  5. Проверить, что задача без скоупа/доступа не сохраняется и объясняет причину.
  6. Проверить, что исключённый участник не попадает в диаграмму, но виден в панели исключений.
  7. Проверить, что блокер без цитаты помечается как неподтверждённый.

Как проверяется

  1. Тесты плагина: run-tests.mjs, api.test.mjs, plugin.test.mjs, build-example.mjs — зелёные.
  2. Пример воспроизводится: example-report.html содержит форму v2.2; check_report.py и validate_analysis.py зелёные.
