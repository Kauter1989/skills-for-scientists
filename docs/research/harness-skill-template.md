## 1. Задача

Задать единый контракт навыка: структуру каталога, frontmatter, обязательные
разделы `SKILL.md`, правила триггеров, артефакты и проверку. Навык нужен,
чтобы новый скилл не превращался в длинный промпт без входов, выходов,
границ и доказательств.

**Не входит в задачу:** писать содержание за автора, оценивать качество
чужих навыков (это `harness-skill-audit`) и измерять эффективность
(`harness-skill-eval`).

## 5. Синтез

- **Повторяющиеся паттерны:** навык — каталог; `SKILL.md` — точка входа;
  описание работает как маршрутизатор; глубина вынесена в `references/`;
  исполняемые проверки — в `scripts/`; примеры обязательны.
- **Противоречия:** одни библиотеки строят тяжёлую методологию
  (`superpowers`), другие ограничиваются форматом (`anthropics/skills`).
  Единого контракта на границы, доказательства и проверку нет.
- **Пробелы:** почти никто не валидирует наличие границ, QA и
  воспроизводимого примера; каталоги растут быстрее, чем проверяются.
- **Что подтверждено эмпирически:** библиотека переиспользуемых навыков
  усиливает агента (Voyager); рефлексия по ошибкам улучшает следующие
  попытки (Reflexion); чек-листы снижают пропуски при наличии владельца и
  измерения (Pronovost).
- **Что является решением автора:** обязательные разделы и локальный
  валидатор. Прямого научного подтверждения для конкретного списка разделов
  нет; это инженерное решение, проверяемое на практике.

## 6. Выводы для дизайна

| Решение | Основание | Альтернатива | Почему не она |
|---|---|---|---|
| `SKILL.md` — короткий контракт, детали в `references/` | Sweller; Agent Skills spec | один большой файл | высокая когнитивная нагрузка, трудно поддерживать |
| `description` содержит «что» и «когда», русские и английские триггеры | Agent Skills spec; `anthropics/skills` | имя файла как единственный ориентир | навык не находится по формулировке задачи |
| Обязательные разделы: вход, процедура, выход, доказательства, границы, ошибки, QA | Pronovost; Reflexion; локальный опыт | свободный Markdown | пропускаются границы и проверка |
| `scripts/validate_skill.py` проверяет структуру и ссылки | пробел в аналогах; AGENTS.md | только ручное ревью | ошибки обнаруживаются поздно |
| `templates/SKILL.md` и `scripts/new_skill.py` | `davila7/claude-code-templates`; `superpowers` | копирование существующего навыка | дрейф структуры и лишние разделы |
| Примеры как эталон входа и выхода | Voyager; Agent Skills spec | только описание | нет доказательства воспроизводимости |

## 7. Открытые вопросы для ревью

2. Должен ли валидатор требовать все разделы или только минимальный набор?
3. Нужен ли отдельный генератор `new_skill.py` или достаточно шаблона?
4. Как проверять качество триггеров, не превращая это в `harness-skill-eval`?
5. Допустимы ли разные шаблоны для `dev`, `sci`, `harness` или контракт должен быть один?
