## 1. Задача

Разворачивать процесс в новом репозитории одной командой: профиль проекта,
`AGENTS.md`, структура `docs/`, хуки, CI и шаблоны research/review. Навык
нужен, чтобы старт не зависел от памяти и не терял половину проверок.

**Не входит в задачу:** устанавливать зависимости, выбирать стек, делать
первый коммит или push, перезаписывать существующие файлы без решения.

## 2. Поисковые запросы

## 5. Синтез

- **Повторяющиеся паттерны:** шаблон с вопросами, декларативный профиль,
  ранние хуки, CI и документация «первый шаг».
- **Противоречия:** чем больше шаблон, тем полнее старт и тем выше
  когнитивная нагрузка. Решение: минимальный обязательный набор, остальное
  — опциональные блоки.
- **Пробелы:** аналоги создают проект, но не связывают профиль, правила,
  research/review и проверки в один воспроизводимый bootstrap. Ни один не
  спрашивает пользователя, какие навыки нужны на старте.
- **Что подтверждено эмпирически:** барьеры новичков связаны с
  документацией и точками входа; онбординг требует явных практик;
  когнитивная нагрузка ограничивает объём стартовой инструкции; качество
  опроса зависит от формулировок и уточнений.
- **Что является решением автора:** состав минимального профиля, формат
  `AGENTS.md`, набор хуков и CI, политика перезаписи, схема опроса и
  формат HTML-утверждения.

## 6. Выводы для дизайна

| Решение | Основание | Альтернатива | Почему не она |
|---|---|---|---|
| Один профиль `profile.yml` как источник команд | Copier; spec-kit | разбросанные команды в docs | нельзя проверить и обновить |
| `AGENTS.md` из шаблона с проектными командами | Steinmacher; практика | общий текст без команд | новичок не знает, что запускать |
| Сначала опрос пользователя, потом scaffold | Boynton; DiCicco-Bloom | сразу создать структуру | можно выбрать неверный набор навыков |
| Итоговый workflow утверждается в HTML | Fagerholm; практика | молча применить | пользователь не видит, что будет создано |
| Минимальный набор: profile, AGENTS, docs, hooks, CI | Sweller | всё сразу | высокая нагрузка и мёртвые файлы |
| `--dry-run` и запрет перезаписи по умолчанию | Copier | сразу писать | риск потерять существующее |
| `check_bootstrap.py` проверяет результат | Fagerholm | «выглядит правильно» | нет доказательства |
| Не устанавливать зависимости и не делать commit | практика | полный автомат | скрытые side effects |

## 7. Решения ревью

1. **Профиль:** `profile.yml` в корне репозитория; команды и стек — в нём.
2. **CI:** GitHub Actions по умолчанию, но блок опциональный.
3. **Перезапись:** только с явным `--force`; по умолчанию ничего не
   перезаписывается.
4. **Шаблон:** один язык-агностик; stack-specific блоки — опциональны.
5. **Минимальный bootstrap:** `profile.yml`, `AGENTS.md`, `docs/`,
   hooks, CI.
6. **Опрос обязателен.** До scaffold задаются вопросы о типе работы,
   стеке, командах, ролях, стартовых задачах и ограничениях.
7. **Утверждение обязательно.** Итоговый workflow и набор навыков
   показываются в `bootstrap-plan.html`; scaffold выполняется только после
   `approved` пользователем.

Вопросы опроса:

1. Какой тип работы: разработка, наука, отчётность, смешанный?
2. Какой стек и команды тестов, линтера, сборки?
3. Какие стартовые задачи: фича, багфикс, релиз, аудит, отчёт, эксперимент?
4. Кто работает в репозитории и какие роли нужны?
5. Какие ограничения: приватность, безопасность, ревью, CI?
6. Какие навыки уже есть и какие нужны на старте?
7. Нужен ли минимальный или расширенный workflow?
