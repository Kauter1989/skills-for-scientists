## 1. Задача

Регулярно проверять библиотеку навыков: структуру, дубли триггеров, наличие
артефактов, актуальность команд, ссылки и покрытие доменов. Навык нужен,
чтобы качество библиотеки не зависело от памяти автора и не проверялось
«на глаз» только при добавлении очередного навыка.

**Не входит в задачу:** исправлять найденное, оценивать пользу навыка (это
`harness-skill-eval`) и создавать правила (это `harness-rule-to-mechanism`).

## 5. Синтез

- **Повторяющиеся паттерны:** сначала машинные проверки (структура, ссылки,
  дубли, наличие артефактов), затем выборочная смысловая проверка. Отчёт
  должен содержать evidence, severity и владельца.
- **Противоречия:** полный аудит дорог, выборочный — может пропустить
  дефект. Решение: риск-ориентированная выборка плюс обязательные
  детерминированные проверки для всех навыков.
- **Пробелы:** аналоги проверяют код, промпты или ссылки, но не связывают
  контракт навыка, триггеры и покрытие доменов. Эту часть закрывает
  собственный чек-лист.
- **Что подтверждено эмпирически:** формальная инспекция снижает число
  дефектов; согласие оценщиков нужно измерять; системы деградируют без
  обновления.
- **Что является решением автора:** severity-шкала, порог дублей, формат
  отчёта и периодичность аудита.

## 6. Выводы для дизайна

| Решение | Основание | Альтернатива | Почему не она |
|---|---|---|---|
| Сначала детерминированные проверки, потом выборка | Fagan; markdownlint | только ручное чтение | дорого и неповторяемо |
| Дубли триггеров считаются по описанию и вручную | jscpd; Cohen | только текстовое сходство | ложные пары и пропуски |
| Severity: blocker / major / minor | Fagan | «важно / неважно» | нет приоритета исправлений |
| Отчёт с evidence и владельцем | Fagan; практика | список замечаний | непонятно, что и кому чинить |
| Регулярный аудит и тренд | Parnas | разовый аудит | библиотека деградирует молча |
| Два независимых прохода для спорных находок | Cohen | один оценщик | низкая надёжность суждения |

## 7. Решения ревью

1. **Отчёты:** `docs/audits/<date>.html`; JSON-снимок рядом —
   `docs/audits/<date>.json`.
2. **JSON для тренда:** нужен, чтобы сравнивать покрытие, дубли и
   ложные срабатывания между аудитами.
3. **Дубли:** по умолчанию дублей быть не должно. Любая пара похожих
   триггеров — находка; блокирующий статус и исключения утверждает
   пользователь.
4. **Severity спорной находки:** утверждает владелец домена или
   пользователь; второй проход обязателен для blocker.
5. **Периодичность:** перед релизом и по событию — новый навык,
   изменение контракта, крупное изменение карты.
