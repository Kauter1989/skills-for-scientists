# Outbox — очередь сообщений на отправку

Норматив механизма отправки из отчёта формы v2. HTML-отчёт автономен: он не
хранит токен и не делает сетевых запросов. Кнопка «Отправить» в отчёте только
ставит черновик в очередь; отправку выполняет плагин или агент отдельным
подтверждённым вызовом.

## 1. Состояние кнопок

- Кнопка активна только если `account.scopes` содержит `messages:create`.
- Без скоупа кнопка неактивна (`disabled`) с причиной «токен только на чтение
  (нет messages:create)». Это состояние по умолчанию для read-only токенов.
- У каждого черновика указан канал назначения: название чата и `#chatId`;
  для личного чата — «Личный чат» (и имя собеседника, если известно).
- Черновик редактируется в отчёте (textarea) и повторно вычитывается в диалоге
  перед постановкой в очередь.

## 2. Файл очереди

Каталог: `.pachca/outbox/`. Имя: `pachca-outbox-<chatId>-<timestamp>.json`.

```json
{
  "schemaVersion": 1,
  "kind": "pachca-outbox-message",
  "id": "ob-<base36 time>-<random>",
  "queuedAt": "2026-11-19T08:00:00.000Z",
  "chatId": "1",
  "channel": "Платформа",
  "text": "текст черновика",
  "source": { "report": "заголовок отчёта", "ref": "A-4 | blocker:<проект>:<n>" },
  "status": "pending_confirmation",
  "sendPolicy": "confirm_then_send"
}
```

Требования:

- `chatId`, `channel`, `text` — обязательны; `text` не пустой;
- `status` при создании всегда `pending_confirmation`;
- токен, пароли и иные секреты в файл не пишутся;
- `source.ref` связывает сообщение с карточкой отчёта (личное действие `A-n`
  или блокер проекта) для проверяемости.

## 3. Запись из браузера

1. Основной путь: File System Access API — `showDirectoryPicker` (один раз,
   пользователь выбирает `.pachca/outbox/`), handle хранится в IndexedDB
   (`pachca-outbox` / `handles` / `dir`), права проверяются `queryPermission`
   и при необходимости запрашиваются `requestPermission` в обработчике клика.
   Запись: `getFileHandle(name, {create:true}) → createWritable → write → close`.
2. Фолбэк (API недоступен, отказ в доступе, отмена выбора): файл скачивается
   через Blob + `a.download`; отчёт показывает инструкцию положить файл в
   `.pachca/outbox/`. Ограничение поддержки браузерами фиксируется честно.
3. Диалог отправки (`dialog#send-dialog`) показывает канал и финальный текст,
   кнопки: «В очередь на отправку», «Скопировать текст», «Отмена».
4. Никаких сетевых запросов из HTML: `fetch`, `XMLHttpRequest`, WebSocket
   запрещены контрактом отчёта.

## 4. Обработка очереди (агент/плагин)

1. Прочитать `.pachca/outbox/*.json` со статусом `pending_confirmation`.
2. Показать пользователю каждое сообщение: канал, текст, источник. Получить
   отдельное явное подтверждение по каждому. Без подтверждения не отправлять.
3. Preflight перед отправкой (как для задач, см. `tasks.md`):
   - скоуп `messages:create` у токена;
   - роль в чате owner/admin/editor (подписчик канала писать не может);
     роль подтверждается отдельными запросами `role=...`, не общим списком;
   - чат не архивный;
   - права не изменились с прошлого запуска.
4. Отправка: MCP `pachca_send_message` (или REST с тем же preflight).
   Автоматическая пакетная отправка без подтверждения запрещена.
5. После отправки: файл переносится в `.pachca/outbox/sent/` и/или получает
   `status: "sent"` + `messageId` + `sentAt`. При отказе прав —
   `status: "rejected"` + `reason`; файл остаётся для разбора.
6. Повторная постановка того же черновика создаёт новый файл; дедупликация —
   по `source.ref` + `text` на усмотрение агента, но не молчаливая.

## 5. Границы

- Outbox не обходит права: при read-only токене кнопки неактивны, а обработка
   очереди без `messages:create` невозможна и объясняет причину.
- Отчёт не отправляет сообщения сам по себе, даже если скоуп есть.
- Личные чаты: отправка в личный чат требует членства и тех же прав; черновик
   личного действия адресован именно тому чату, который указан в карточке.
- Очередь — локальное состояние пользователя; в репозиторий навыка файлы
   очереди не коммитятся (как и всё `.pachca/`).
