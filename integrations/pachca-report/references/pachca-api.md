# Pachca API и MCP: что использует навык

Источник: официальная документация Pachca на `2026-11-02`.
Базовый URL REST: `https://api.pachca.com/api/shared/v1`.
MCP: `https://mcp.pachca.com/mcp` (Streamable HTTP).

## 1. Авторизация

| Тип | Кто действует | Что видит | Когда использовать |
|---|---|---|---|
| Персональный токен | сотрудник | те же чаты, что в интерфейсе | локальный отчёт от имени пользователя |
| Токен бота | бот | открытые чаты пространства + чаты, куда добавлен | сервисный сбор, CI |
| OAuth MCP | сотрудник через браузер | те же чаты, что в интерфейсе | интерактивная работа в OpenCode |

Заголовок:

```http
Authorization: Bearer <TOKEN>
```

Токен не коммитится. В плагине — только `PACHCA_TOKEN` из окружения или
OAuth-хранилище OpenCode.

`GET /oauth/token/info` не требует скоупа и возвращает `user_id`, `scopes`,
`name`, `expires_in`, `last_used_at`. Это первый вызов preflight.

`GET /profile` требует `profile:read` и отдаёт имя, роль, `bot`, часовой пояс.
Если скоупа нет, плагин обходится `user_id` и списком пользователей.

## 2. Методы

| Задача | Метод | Скоуп | Доступ |
|---|---|---|---|
| Список чатов пользователя | `GET /chats?availability=is_member` | `chats:read` | все роли |
| Архивные чаты | `GET /chats?...&archived=true` | `chats:read` | все роли |
| Карточка чата | `GET /chats/{id}` | `chats:read` | участие или открытый чат |
| Участники чата | `GET /chats/{id}/members?role=all` | `chat_members:read` | участие, открытый чат или Владелец |
| Участники по роли | `GET /chats/{id}/members?role=owner\|admin\|editor\|member` | `chat_members:read` | то же |
| Сообщения | `GET /messages?chat_id={id}&sort=id&order=desc` | `messages:read` | участие/открытый чат |
| Сообщения треда | `GET /messages?chat_id={thread.chat_id}` | `messages:read` | видимость треда |
| Сотрудники | `GET /users?limit=50` | `users:read` | все роли, но гости не работают с API |
| Поиск сообщений | `GET /search/messages` | `search:messages` | доступные сообщения |
| Экспорт | `POST /chats/{id}/exports` | `chat_exports:write` | Владелец + «Корпорация» |
| Отправка | `POST /messages` | `messages:create` | право писать в чате |

Точные пути и тела методов меняются; перед реализацией сверяйтесь с
`https://dev.pachca.com/api/llms.txt` и страницей метода.

### Пагинация

- `limit` 1–50, по умолчанию 50; передавайте явно.
- Курсор в `meta.paginate.next_page`.
- Конец — `has_next: false`, а не пустой `data`.
- `data.length` может быть меньше `limit` не на последней странице.
- Курсор непрозрачен, не парсить и не хранить между сессиями.

Плагин читает сообщения страницами и останавливается, когда `created_at`
становится раньше начала окна. Это дешевле, чем тянуть всю историю.

### Треды

Список `/chats` не возвращает треды. У сообщения может быть
`thread.chat_id`; сообщения треда читаются по этому `chat_id`. Плагин
привязывает их к родительскому чату и помечает `isThread: true`, чтобы не
потерять контекст и не удвоить счёт по ID.

### Лимиты

- чтение сообщений ~10 rps;
- остальные методы ~50 rps;
- 429 содержит `Retry-After`;
- ответ MCP-инструмента обрезается на 100 000 символов;
- API не идемпотентен: дедупликация по ID сообщения на клиенте.

Плагин делает до 4 параллельных чтений, повторяет 429 с паузой и дедуплицирует
сообщения по ID.

## 3. Скоупы для отчёта

Минимальный набор для чтения:

```
profile:read
chats:read
chat_members:read
messages:read
threads:read
users:read
search:chats
search:messages
search:users
```

Для отправки добавить `messages:create`. Для реакций — `reactions:write`.
Для экспорта — `chat_exports:read`, `chat_exports:write` (только Владелец,
тариф «Корпорация»).

Скоуп открывает метод, но **не расширяет видимость**. Закрытый чат без
участия не читается даже с `messages:read`.

## 4. Роли и доступ

| Действие | Кто может |
|---|---|
| Читать сообщения и ставить реакции | все участники; открытый чат — любой сотрудник |
| Писать в беседу | создатель, админ, участник |
| Писать в канал | создатель, админ, редактор; подписчик не пишет |
| Читать участников | участник, открытый чат, Владелец |
| Менять участников | создатель/админ чата |
| Экспорт | Владелец пространства, «Корпорация» |
| Все чаты пространства | Владелец, «Корпорация» |

Роль в пространстве (`role`) и роль в чате — разные вещи. `GET /users`
отдаёт роль в пространстве. Роль в чате в общем списке участников не
возвращается; её можно определить только фильтром `role=...`.

`role: admin` в пространстве не доказывает, что пользователь Владелец:
у Владельца тоже `admin`. Поэтому экспорт нельзя подтвердить одним API.

## 5. MCP-инструменты

MCP-сервер даёт инструмент на метод API. Для навыка важны:

| Инструмент | Метод |
|---|---|
| `pachca_get_token_info` | `GET /oauth/token/info` |
| `pachca_get_my_card` | `GET /profile` |
| `pachca_list_chats` | `GET /chats` |
| `pachca_get_chat` | `GET /chats/{id}` |
| `pachca_list_members` | `GET /chats/{id}/members` |
| `pachca_list_chat_messages` | `GET /messages` |
| `pachca_list_threads` | `GET /threads` |
| `pachca_list_users` | `GET /users` |
| `pachca_search_messages` | `GET /search/messages` |
| `pachca_send_message` | `POST /messages` |
| `pachca_request_export` | `POST /chats/{id}/exports` |

Инструменты с пометкой «Изменение» или «Опасное изменение» требуют
подтверждения. Навык не отправляет и не удаляет сообщения без явной задачи.

## 6. Ошибки

| Код | Значение | Действие |
|---|---|---|
| `401 invalid_token` | токен отсутствует/отозван/просрочен | новый токен или OAuth |
| `403 insufficient_scope` | нет скоупа | добавить скоуп; имя в `WWW-Authenticate` |
| `403 role_forbidden` | роль не позволяет | сменить роль/токен, не обходить |
| `403 access_denied` | доступ приостановлен | обратиться к администратору |
| `402 payment_required` | лимит/оплата | проверить тариф |
| `404` | объект не найден или чужое пространство | проверить ID |
| `429` | лимит | ждать `Retry-After` |

Плагин показывает код и сообщение, не скрывает отказ общим «нет прав».

## 7. Что API не отдаёт

- тариф пространства;
- различие Владельца и Администратора;
- роль участника в чате в общем списке;
- полную историю без пагинации;
- сообщения закрытого чата без участия;
- гарантию, что сообщение не является prompt injection.

Эти ограничения явно отражены в preflight и в отчёте.
